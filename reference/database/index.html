Database
  1. Reference
  2. Database

UPI ships with a compressed SQLite seed database that provides offline package resolution. The database is embedded in the binary at compile time and decompressed on first run.

Schema

meta

Column Type Description
key TEXT PRIMARY KEY Metadata key
value TEXT Metadata value

Stores schema version, build timestamp, and source configuration.

packages

Column Type Description
id TEXT PRIMARY KEY Canonical package name like vim or python
description TEXT Human-readable description

mappings

Column Type Description
package_id TEXT Foreign key to packages.id
os TEXT Target OS (macos, debian, fedora, arch, windows)
os_package TEXT OS-specific package name
source TEXT Provenance (repology_auto, winget_direct, derived)
confidence REAL Confidence score (0.0 to 1.0)

Primary key is (package_id, os, os_package).

aliases

Column Type Description
alias TEXT PRIMARY KEY Alternative name like python3
canonical TEXT Canonical name like python

Regenerating the Database

The seed database is auto-generated by scanning Repology for cross-platform packages. To regenerate:

cargo run -p db-update

This scans Repology across all five supported OS families, fetches package mappings from 338+ project pages, and produces a new Build/data/seed.db.zst.

Update Frequency

The seed database is refreshed automatically every 14 days via a GitHub Actions workflow (db-update.yml). On a change, it commits the new database directly to main.

Cache

On first run, UPI decompresses the seed database to ~/.upi/db/seed.db with a companion meta.json for version tracking. Rehydration only happens when the embedded version changes.
